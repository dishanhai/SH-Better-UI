# UMIVP 仓库与材质审计

基线为 `d87e31ebe5cafd39b2c7dd48111e21327a943b17` 加审计时工作区。现有受管 Glass、Spatial、Live Surface 等源码含未提交改动。本报告记录 UMIVP 实施前可见的入口，新增目录的实际收录及缺口见 [覆盖报告](material-coverage-report.md)。

## 源集与登记路径

- Forge 1.20.1 使用 Java 17 的根工程。NeoForge 1.21.1 使用 Java 21 的 `neoforge/` 工程。两者编入 `src/kernel/java`，NeoForge 还复用 `src/main/java`、`src/main/kotlin` 和 `src/main/resources`，并替换入口、事件、部分顶点、后处理和兼容适配。相关差异包括 `GaussBlur`、`IconShaderRenderer`、`CapsuleRenderer`、`VisualRevealRenderer`、`PlatformSpatialVertices`、`GlassTooltip` 和歌词字形适配。见 [Forge 构建](../build.gradle)、[NeoForge 构建](../neoforge/build.gradle)、[共享内核源集](../gradle/kernel.gradle)。
- 公共服务由 `UnifiedUI.get()` 或 `ModuleContext.engine()` 获取 `UIEngine`，按 `ServiceKey<T>` 调用 `find` 或 `require`。`ClientUiKernel` 以 `BuiltinService` 登记 `RENDER`、`GLASS`、`SPATIAL`、`THEME`、`RESOURCES`。渲染命令受原生 Screen/HUD pass、作用域和模块权限约束。审计基线没有 `UIApis.MATERIAL_CATALOG` 或统一效果注册表。见 [内核 API](public-api.md)、[模块开发](module-development.md)、[UIApis](../src/main/java/com/dishanhai/sh_better_ui/kernel/api/UIApis.java)、[ClientUiKernel](../src/main/java/com/dishanhai/sh_better_ui/kernel/internal/ClientUiKernel.java)。
- `ShBetterUiApi.backgrounds()` 初始化 `BuiltinBackgrounds`，`BackgroundSpec` 的工厂按页面创建 `BackgroundLayer` renderer。`BackgroundRegistry` 支持受控登记、快照、查找及句柄撤销。`ShBetterUiApi.developerPreviews()` 单独初始化 `BuiltinPreviews`，包含 `DeveloperSamples` 及附加场景。`PreviewSpec` 的命名空间 ID、排序、分类、标题键和懒创建场景属于预览声明。`UiClientApi.registerDeveloperPreview(...)` 和 `PreviewRegistry.Registration` 可用于第三方登记与撤销。背景短 ID 和预览短 ID 需分别解析。见 [背景和画廊 API](API_REFERENCE.md)、[背景登记](../src/main/java/com/dishanhai/sh_better_ui/client/api/BuiltinBackgrounds.java)、[画廊登记](../src/main/java/com/dishanhai/sh_better_ui/client/gui/panel/BuiltinPreviews.java)、[PreviewSpec](../src/main/java/com/dishanhai/sh_better_ui/client/api/preview/PreviewSpec.java)。
- `MaterialsApi.themeChoices/findTheme` 枚举旧 `GlassTheme` 预设及 `ThemeManager` 注册的动态主题。`ThemeEffects` 按组提供不可变 profile 和 JSON 局部覆写，实际字段约束在各 record 构造器，`ThemeEffectRanges` 是编辑器滑杆约定。`ThemeEffectEditor` 深拷贝草稿，经 `ThemeEffects.preview` 在线程局部渲染，确认时把副本交给宿主。`ClientUiSettings` 持有客户端配置，资源包主题另有主题 schema、重载和作用域。两套原有配置均可作为相应效果的参数证据。见 [动态主题](DYNAMIC_THEMES.md)、[效果配置](../src/main/java/com/dishanhai/sh_better_ui/client/gui/scaled/ThemeEffects.java)、[效果编辑器](../src/main/java/com/dishanhai/sh_better_ui/client/gui/scaled/ThemeEffectEditor.java)、[主题预览](../src/main/java/com/dishanhai/sh_better_ui/client/gui/panel/ThemeEffectPreview.java)。
- `examples/kernel-extension` 分别编译两端消费方。`ExampleUiModule.CounterPage` 探测 `UIApis.GLASS`，在 Screen 作用域登记 pass，同一动画进度插值 `GlassDraw` 后绘制前景文字。示例将 SH-Better-UI 作为外部依赖。其他效果已有画廊 `PreviewSpec.code()`、`API_REFERENCE.md`、`docs/effects.md` 或 `docs/spatial/` 示例。见 [消费项目](../examples/kernel-extension/README.md)、[实际示例调用](../examples/kernel-extension/common/src/main/java/com/dishanhai/shbui_kernel_example/ExampleUiModule.java)。

## 清单的证据约定

表中 `共享` 表示两端构建接入同一 API 和主体实现。`适配` 表示有独立的 Loader 绘制或资源注册适配。`历史原生` 表示已有客户端结果文件或报告，范围限于对应场景。`未适配` 表示审计基线未找到 WebGL 2 renderer。`编辑器` 表示 `ThemeEffectEditor` 或 `ThemeEffectPreview` 的局部示例。表中画廊 ID 省略共有前缀 `sh_better_ui:`。

`Source` 以 Java 文件名标注。渲染和背景实现主要位于 [client/gui/scaled](../src/main/java/com/dishanhai/sh_better_ui/client/gui/scaled/)、[client/gui/display](../src/main/java/com/dishanhai/sh_better_ui/client/gui/display/) 和 [client/api](../src/main/java/com/dishanhai/sh_better_ui/client/api/)。`Shader` 以 [资源根](../src/main/resources/assets/sh_better_ui/shaders/) 为起点。`Public API` 中 `materials()`、`graphics()`、`motion()` 和 `blur()` 均来自 `ShBetterUiApi`。

## 验证边界与实施风险

- 源码检查交叉核对公共 facade 与 UUK 服务、背景/画廊实际登记、Shader 和纹理、示例、测试源集。已有 `kernelTest`、客户端 `test`、`verifyLibraryJar`、`gradle/kernel-smoke.init.gradle`、`gradle/kernel-client-benchmark.init.gradle` 及独立消费方的构建。Phase 0 只执行静态核对，未在此阶段重跑 Gradle 或启动客户端。
- 2026-11-10 工作区已有 `build/kernel-verification/client-forge-uuk-glass-final/success.txt` 和 `build/kernel-verification/client-neoforge-uuk-optics-reload/success.txt`。两者记录原生受管 Glass 的共享捕获、光学和对比像素、GL 状态、实色回退、Shader 编译故障后重载恢复、HUD 和关闭释放。`build/kernel-benchmark/native-{forge,neoforge}-spatial-full/success.txt` 与 [Spatial 验证记录](SPATIAL_VERIFICATION.md) 提供历史空间渲染证据。旧截图与运行记录对应当时工作区，不覆盖新增目录路由、Web、其他操作系统或不同 GPU。
- WebGL 2 要单独检查 GLSL ES 精度、色彩空间、alpha、GUI 到 framebuffer 坐标、采样偏移和硬件能力。受管 Glass 的首个光学绘制前捕获策略与旧浮层的逐层采样语义不同。画廊对照要确保背景、前景、时钟、输入及参数相同。
- 参数来源存在构造器范围、主题编辑器滑杆步长、宿主场景参数三层。录入时保留实际约束来源，场景初始值与 Java 材质默认值分开记录。注册撤销与资源重载时需重新解析有效预览句柄。

首个可运行切片选 `sh_better_ui:liquid_glass`。使用真实 `GlassService` 与 `RenderService`，单独登记能调用受管 Glass 的 `PreviewSpec`，再以 `GlassOptics` 的七项参数和 `GlassMaterial` 的枚举预设打通目录、草稿和预设。保持旧版效果及其预览 ID 原有路由。
