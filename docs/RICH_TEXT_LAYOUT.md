# 富文字行盒、換行與命中

`RichTextLayout` 計算一個內容盒。既有 `AlignmentLayout` 決定這個盒子在 Screen 中的位置、姿態及裁剪。畫面與輸入以最後成功繪製的 `Presentation` 為準；模型變更或資源重載後要等下一次成功繪製才恢復命中。

- Minecraft 適配器使用同一樣式和 `FormattedCharSequence` 量測、繪製。預設字型使用原生 provider chain；缺少指定字型資源定義時改用預設字型。具有字型定義但缺少特定字形時採原生缺字行為。示例適配器使用 `lineHeight - 2` 的 ascent 和 `2` 的 descent，未提取字形墨跡邊界。
- 圖片預設以整個字型行高為目標高度，寬度按宣告比例推導。若太寬，先等比縮到可用寬，再以整數邏輯像素取整，每邊最少 1 像素。圖片不可分割，剩餘寬度不足時另起一行。實際 PNG 的比例若與宣告不同，仍等比置中於保留盒。
- 圖片和替換物件底邊在文字基線。`RichObjectNode` 可指定邏輯高度，再按同一比例規則縮進視口。每行的 ascent 取文字 ascent 與同行物件高度的最大值，底下保留文字 descent。`ParagraphBreak` 結束該行並加入宣告間距。
- 硬換行依各 `TextRun` 的 Unicode 換行序列處理，同一 run 的 CRLF 算一次。軟換行使用 JDK `BreakIterator` 的行斷點，沒有合適斷點時在 Unicode 17 擴展字素邊界折行。軟換行丟棄行尾及移到下一行的完整分隔空白字素。單一過寬字素保持尺寸，由宿主局部裁剪。文字按節點順序排版，跨 run 的字形合併或 CRLF 合併待實作。 [字素驗證與資料來源](p9-typography.md)
- `Fragment.bounds()` 和 `hitTest` 使用同一半開矩形。圖片的透明像素或因比例差異產生的留白仍屬該節點盒，命中只代表幾何。原生適配器先檢查當幀有效裁剪，再反轉已呈現的 GUI 轉換；GUI Scale 留給宿主與 Minecraft 投影。
- 文字片段有原始 run 的 UTF-16 偏移。選取使用字素邊界，順向及逆向範圍共用同一複製契約。原生適配器將含雙向文字的片段交由 Minecraft 做視覺順序和可用的字形處理。此類片段暫停點擊光標映射，避免把邏輯索引當成視覺索引。
- 捲動只改變呈現轉換。View 反投影實際裁剪四角，二分取得垂直相交行。旋轉時相交行採保守包圍，實際繪製仍由原生 scissor 裁剪。只有可見行會提交前景、維護控件命中索引及按需取得文字序列；文件量測仍建立完整行盒。

完整段落級雙向重排、跨樣式塑形、CJK 禁則調校、任意文字尺寸、視覺選取、Ruby、浮動和分欄仍列在後續驗收。自訂度量器須遵守前綴寬度契約。 [API](RICH_TEXT_API.md)
